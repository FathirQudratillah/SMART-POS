# 2. Rincian tabel dan kolom

Untuk kolom umum, gunakan `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` atau strategi ID yang konsisten dengan Laravel. Tabel transaksi umumnya memiliki `created_at` dan `updated_at`, sedangkan tabel relasi sederhana bisa menyesuaikan kebutuhan.

Tabel master menggunakan soft delete melalui kolom `deleted_at`: perusahaan, cabang, pengguna, role, permission, kategori, produk, gudang, pelanggan, pemasok, pengaturan perusahaan, metode pembayaran, dan paket langganan. Data yang dihapus tetap tersimpan dan tidak muncul pada query Eloquent biasa; nilai unik dapat digunakan kembali setelah record lama dihapus. Tabel relasi, detail transaksi, ledger, dan audit tidak menggunakan soft delete agar histori dan perhitungan tetap utuh.

# 3. Aturan relasi dan keamanan yang wajib

Pemisahan schema tidak otomatis mengamankan data. Terapkan aturan berikut:

- Semua data bisnis yang dimiliki perusahaan memiliki `company_id`, secara langsung atau melalui relasi yang tervalidasi.
- Nomor dokumen seperti `invoice_no`, `purchase_no`, dan `transfer_no` menggunakan unique constraint yang sesuai, umumnya per perusahaan.
- Foreign key lintas-schema menggunakan nama tabel yang lengkap dan direferensikan dengan benar.
- Transaksi checkout, pembayaran, retur, dan perubahan stok dijalankan dengan database transaction.
- Dokumen yang sudah diposting tidak dihapus sembarangan; gunakan status pembatalan dan catatan audit.
- Pastikan foreign key tidak hanya memeriksa keberadaan ID, tetapi juga menjaga agar relasi tidak melintasi perusahaan secara tidak sah. Ini bisa dilakukan dengan constraint gabungan yang dirancang tepat atau validasi backend yang kuat.

## 4. Urutan pembuatan migration

Jangan langsung membuat seluruh tabel sebelum pola schema dan relasinya diuji. Gunakan urutan ini:

1. Buat schema `core`, lalu tabel perusahaan, cabang, dan pengguna.
2. Buat schema `access` beserta role dan permission.
3. Buat `catalog`.
4. Buat `inventory`.
5. Buat `settings` lebih awal untuk menyiapkan metode pembayaran sebelum transaksi penjualan.
6. Buat `sales`.
7. Buat `purchasing`.
8. Buat `finance` dan `audit`.
9. Jalankan pengujian migration, foreign key, dan isolasi data perusahaan.

Catatan teknis Laravel: migration bawaan biasanya membuat tabel di schema pada `search_path`. Untuk struktur ini, kita perlu menentukan secara eksplisit cara membuat tabel pada schema tujuan, menangani foreign key lintas-schema, dan menguji perilaku Eloquent. Jangan mengandalkan perubahan `search_path` saja tanpa memeriksa schema tempat tabel benar-benar dibuat.

Dengan struktur ini, database kamu terorganisir menurut modul bisnis tanpa perlu membuat database terpisah untuk setiap perusahaan.
